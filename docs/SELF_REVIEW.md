# Self-review

Основной упор сделал на то, чтобы импорт нормально переживал обрыв сети, перезапуск и отмену. В таком сценарии важно понимать, что уже произошло на сервере, и давать пользователю понятное действие, если что-то пошло не так.

Три основных решения.

1. **Сохранять состояние до запроса.** Ключ операции записывается до POST. Если ответ потерялся, приложение ищет импорт по этому ключу. После перезапуска файл сам повторно не отправляется. Старый ответ сервера не откатывает готовый отчёт, а удаление считается завершённым только после GET со статусом `deleted`.

2. **Вынести логику из экранов.** Сценарием управляет отдельный контроллер. Сеть, файлы и хранилище подключаются через адаптеры. Экраны разделены через native stack, повторяющиеся элементы вынесены в общие UI-компоненты. Так можно менять интерфейс и проверять бизнес-логику независимо.

3. **Проверять файл до отправки.** Проверяю содержимое и фактический размер, чтение идёт блоками. Ложный PDF и файл больше 10 МиБ отклоняются до POST. Своя временная копия удаляется при отмене или после сохранения jobId. Если очистка не удалась, запись сохраняется для повтора.

Ради срока оставил один активный импорт и опрос сервера, пока приложение открыто. Проверка формата рассчитана на файлы из задания. Отправка буферизует до 10 МиБ. Системный picker может скопировать большой файл ещё до проверки. Отдельного фонового worker и шифрования журнала операций нет. Эти ограничения подходят для синтетических данных задания.

В production первыми рисками считаю удалённые файловые провайдеры, нехватку места и очистку кэша при неизвестном исходе POST. Для реальных документов нужны контролируемое копирование и потоковая отправка, защищённый журнал, HTTPS и фоновая сверка с сервером. Следил бы за дублями job, откатами статуса, ошибками очистки и временем восстановления. Содержимое документов и имена файлов в метрики не попадали бы. При дублях или ложном подтверждении удаления остановил бы rollout.

Пользовался Codex для реализации и рефакторинга. С его помощью автоматизировал тесты и проверки на эмуляторах. Вручную проверил приложение на личном iPhone с iOS и Google Pixel с Android. Прошёл выбор файла, отправку, получение отчёта и открытие "Подробнее". Отдельно вручную проверял архитектурные решения. По ходу работы давал обратную связь по ошибкам и интерфейсу.
