# Self-review

1. **Durable intent до HTTP.** Create/delete UUID сохраняются до запроса. Lost ACK восстанавливается через GET с прежним ключом; 404 не разрешает автоматическую отправку. Revision не уменьшается, deleted остаётся tombstone. Deadline 12 секунд освобождает UI; поздний ответ не меняет состояние. Отмена сохраняет только metadata для последующего удаления и удаляет локальную копию. Серверное удаление подтверждает только GET deleted.

2. **Один владелец сценария.** Core controller не зависит от React/native API; адаптеры отвечают за сеть, файлы и storage. Один provider сохраняет controller между native stack screens. Чистая presentation-функция и общие Button, IconTile, SheetLayout отделяют состояние от интерфейса. AST-проверка контролирует направление зависимостей. На маленьком экране действия прокручиваются; display typography ограничена 125%, основной текст и кнопки сохраняют системный масштаб.

3. **Приватные временные байты.** Валидация проверяет содержимое блоками до 64 КиБ, суммарно до 10 МиБ + 1 байт. Upload принятого файла буферизуется до 10 МиБ; это не streaming. Нативный wire-аудит обнаружил, что Expo File подменял MIME на iOS; Uint8Array сохраняет application/octet-stream. Копия под UUID удаляется при отмене или durable jobId; picker cache и iOS Inbox тоже очищаются. При ошибке очистки запись сохраняется, новый выбор блокируется. Исходный документ не меняется. Аналитики и raw logging нет, redirects запрещены.

Упрощения: один импорт, foreground polling и конечная очередь отмен без фонового worker. Проверка PDF/CSV рассчитана на synthetic kit. Picker может скопировать большой файл до проверки размера; ОС может удалить cache. AsyncStorage отдельно не шифруется и на iOS может попасть в backup. Только синтетические данные.

В production первыми рисками будут удалённый provider, нехватка диска и eviction при неизвестном POST. Нужны bounded native copy/upload, защищённый journal, HTTPS и серверная reconciliation. Rollout останавливают дубли job, rollback revision, ложное подтверждение удаления, утечки или устойчивый cleanup failure. Метрики не должны содержать документы, имена или описания операций.

AI использовался для реализации, тестов и review. Последний check агента: 89 клиентских, 11 toolchain и 6 оригинальных mock-тестов, проверка неизменности kit. Release-сборки и native UI сценарии проверялись на обеих платформах; даты, версии, HTTP traces, видео и ограничения — в FINAL_ACCEPTANCE. Это проверки агента; кандидат должен самостоятельно воспроизвести README и уметь объяснить решения.
