# Дизайн Statement Import · 30 октября 2026

## Цель и границы

Сделать нативный, визуально собранный fintech-интерфейс для существующего задания. Сценарий остаётся одним: выбрать синтетическую PDF/CSV выписку, проверить метаданные, подтвердить отправку, получить регулярные списания, открыть подробности, удалить импорт. Все цифры приходят из mock. Новые банковские функции, графики, категории, история, аккаунты и нижняя навигация не добавляются.

## Система

- Светлый фон `#F8FAF9`, белые поверхности, графит `#182820`, вторичный текст `#5C6B63`, единый акцент `#CBF28B`. Ошибка имеет отдельный семантический красный.
- Системный SF/Roboto, поддержка кириллицы и системного увеличения шрифта. Числа используют tabular numerals; не уменьшаются принудительно и могут переноситься при accessibility-размере.
- Базовый шаг 4/8 pt; поля 24, карточки 22–24; согласованные радиусы 14/16/24/28.
- Основное действие ≥56 pt, иконки-действия 48×48 pt; текстовые кнопки растут с Dynamic Type. Нет фиксированной высоты текстовых карточек.
- Phosphor: один стиль пиктограмм; монограммы в списке не притворяются логотипами компаний. Знак Receipt используется в UI, app icon и splash, MIT attribution в assets.
- Вариативность 4/10: характер через сумму, цвет и ритм. Движение 2/10: native sheets и короткая анимация splash; Reduce Motion учитывается. Плотность 4/10: результат и действия доступны без технических объяснений на первом плане.

## Реализация по шагам

1. Сохранить controller/runtime и исходный kit. Проверить обязательные сценарии и native selectors.
2. Вынести токены и повторяемые controls в `src/ui`. Сделать empty/selected/ready, компактный tappable список и detail sheet; адрес сервера перенести в sheet настроек.
3. Перенести truthful recovery, queued/processing, delete pending/failure/confirmed и локальные ошибки в новую композицию. Не считать успешный POST готовым отчётом, а DELETE 202 подтверждением удаления.
4. Добавить `expo-splash-screen`, PNG assets и app icon в `app.json`. Генерировать из MIT Phosphor glyph скриптом `node scripts/generate-brand-assets.mjs`. Пересобрать обе платформы.
5. Проверить TypeScript/core/mock tests, native matrix, крупный шрифт, маленький Android viewport и холодный запуск. Сохранить новые screenshots, обновить сборку на iPhone и документацию.

## Startup и состояния

У начального экрана и состояний отправки одна центральная ось: крупный знак 96×96 pt над текстом, одинаковый отступ 20 pt, действия на всю ширину. Общий IconTile задаёт центрирование, размеры 38/56/96 pt и фон; он используется в Brand, карточке файла и состояниях. Пиктограммы и индикаторы в кнопках занимают центрированный слот 24×24 pt без сжатия. В карточке файла знак 56×56 pt выровнен по вертикальному центру блока имени/статуса. Текстовые блоки и кнопки сохраняют прокрутку и Dynamic Type.

Экран выбора упрощён по обратной связи: один центрированный знак, заголовок «Добавьте выписку», короткое назначение, строка форматов и одна основная кнопка. Убраны большая декоративная upload-карточка, три отдельных badge, отдельная карточка «Готово» и повторное пояснение под кнопкой. После подтверждённого удаления остаётся компактная строка «Импорт удалён». Ошибка очистки по-прежнему блокирует новый импорт и показывает действие восстановления.

Заставка использует глубокий тёмно-зелёный фон `#14271F`, лаймовый знак и двухстрочное название Statement Import. Нативный splash и React overlay имеют одинаковые фон и начальное положение знака. `preventAutoHideAsync()` вызывается до монтирования; после layout и декодирования bundled PNG начинается переход: знак поднимается за 420 мс, название мягко появляется, внизу пульсирует маленькая точка без подписи. Status bar на заставке светлый, после неё возвращается тёмный. Стандартного spinner и выдуманного процента загрузки нет.

По обратной связи пользователя добавлено 1100 мс видимого foreground-времени и 180 мс fade: прежнее скрытие на первом кадре было практически незаметным. При Reduce Motion композиция статична и исчезает без fade. Импорт и его recovery загружаются параллельно под overlay; ошибка сети или journal не продлевает заставку. На время показа основное содержимое скрыто от touch и accessibility. Таймер и анимации очищаются при уходе в фон/unmount. После первого показа overlay удаляется; возврат из фона и из document picker не запускает его заново.

Ready: сумма → число платежей → списания → удаление. Статус и revision доступны в настройках и accessibility value `import-status`, без технической строки на основном экране. Retry сохраняет прежние controller methods и idempotency keys.

Настройки проверяют адрес существующим `validateBaseUrl`; новый адрес действует для следующего импорта в текущем запуске. URL уже начатой операции неизменяем и виден отдельно. Настройки не добавляют сетевых запросов.

## Проверка перед завершением

Применимая часть design pre-flight: один light theme и один акцент, контрастные CTA/inputs, native sizing, читаемые переносы, минимальное число повторных действий, достоверные суммы/статусы, отсутствие fake charts и новых функций. Desktop hero/navigation, bento, marquees, GSAP, изображения для маркетингового сайта и auto dark mode не входят в этот native brief.

При обновлении существующего native проекта обнаружен Expo prebuild edge case: старый пустой `SplashScreen.storyboard` сохранял `<subviews/>`, а конфиг добавлял только constraints/resources. Для миграции удалён только этот сгенерированный файл и повторён iOS prebuild; свежий template создал `imageView`. Проверяется фактический холодный запуск, а не только запись в app.json. Clean checkout уже содержит splash config до первого prebuild.

Публичные Phosphor imports типизируются декларациями пакета; маленький Babel transform переводит runtime imports на отдельные icon modules. Это исключает весь неиспользуемый каталог: измеренный Hermes bundle уменьшился с 6 607 212 до 1 288 396 байт. Конфиг находится в `babel.config.cjs`; после отдельного изменения Babel config в существующем Android build потребуется `app:createBundleReleaseJsAndAssets --rerun-tasks` перед assemble, либо чистая сборка.

Точные результаты сборок и тестов фиксируются в TEST_RESULTS; наличие конфигурации splash само по себе не считается подтверждением его показа.
